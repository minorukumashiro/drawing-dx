# mail-fax-watcher

メール添付ファイル（PDF/PNG/JPEG、迷惑メールフォルダを除く）と FAX受信ファイル（PDF）を、
図面DXプラットフォームのステータス「待機」へ自動登録するローカル常駐ツールです。

index.html（ブラウザ）はメールボックスやLAN上のFAX共有フォルダに直接アクセスできないため、
このNode.jsスクリプトをユーザーPC上でタスクスケジューラから定期実行し、Firestoreへ直接書き込みます。

## 全体の流れ

```
Outlook（受信トレイに新着）
  └─ VBAマクロが対象拡張子の添付だけを自動保存
        ↓
   C:\DrawingWatch\mail-inbox\  ←監視対象フォルダ①

FAX複合機 → \\192.168.100.232\fax\ ←監視対象フォルダ②（既存の仕組みそのまま）

        ↓（タスクスケジューラが30分毎に起動）

  mail-fax-watcher (node index.js)
   - 平日日中(8-20時)30分 / 平日夜間(20-8時)6時間 / 土日祝6時間 の間隔を自己判定してスキップ or 実行
   - 新着ファイルを検出 → status:"待機" として Firestore(workspaces/default) に直接登録
   - 画像は圧縮して images/{id} に、PDFはサイズが収まれば本文ごと登録
   - 書き込み後に少し待って「ブラウザ側の全体上書き同期」に消されていないか確認・自己修復

        ↓

図面DXプラットフォーム（index.html）に「待機」として即座に表示される
（ブラウザは開いていなくてもOK。次回開いたときにも反映される）
```

## セットアップ手順

### 1. 依存パッケージのインストール（このリポジトリ内で1回だけ）

`mail-fax-watcher` フォルダで既に `npm install` 済みです（`firebase-admin` / `sharp` / `japanese-holidays`）。
別のPCに配置し直す場合はこのフォルダで `npm install` を実行してください。

### 2. Firebaseサービスアカウントキーの取得（ユーザー作業・必須）

このスクリプトはブラウザのログイン（Firebase Auth）を経由せず、管理者権限でFirestoreに直接書き込みます。

1. https://console.firebase.google.com/ を開き、プロジェクト `drawing-dx` を選択
2. 左上の歯車アイコン → 「プロジェクトの設定」→「サービス アカウント」タブ
3. 「新しい秘密鍵の生成」をクリック → JSONファイルがダウンロードされる
4. ダウンロードしたファイルを `mail-fax-watcher/serviceAccountKey.json` として保存
   （このファイルは秘密情報です。`.gitignore` 済みなのでGitには含まれません。他人と共有しないでください）

### 3. 監視フォルダの作成

メール添付の保存先フォルダを作成します（パスは任意ですが、以降の手順は下記を前提に書いています）。

```
C:\DrawingWatch\mail-inbox\
```

### 4. config.json の作成

`config.example.json` をコピーして `config.json` を作成し、パスを環境に合わせて編集してください。

```powershell
Copy-Item config.example.json config.json
```

主な項目:
- `sources.mailInboxFolder` : 上記で作成したメール添付保存フォルダ
- `sources.faxFolder` : FAX共有フォルダ（既定で `\\192.168.100.232\fax` を設定済み）
- `excludeNonDrawingDocsByFilename` : `false`（既定）。ユーザー方針「除外に迷ったら入れる」に合わせ、
  注文書/納品書/見積書のファイル名判定による自動除外は無効にしています。有効にしたい場合は `true` に変更してください。
  この判定はファイル名だけを見た粗いヒントで、該当ファイルにもタグを付けた上で通常どおり「待機」に取り込みます。
  実際にそれが「単なる発注書」か「加工指示書（実質は図面代用）」かは、drawing-DX側の「待機の一括整理」や
  図面登録画面で人が「種別」を選んで判断する（後者なら図面として種別＝加工指示書で登録、前者なら登録せず
  既存図面に紐づけるだけ）。この振り分けはこのツールでは行わない。
- `skipNonWorkImages` : `true`（既定）。メール署名のロゴ・アイコン等「仕事に不要な小さい画像」を取り込まない。
  判定は**画素サイズ**が主で、`minImageDimension`（既定500px）未満の画像を署名/ロゴとみなして除外する
  （図面は写真・スキャン・本文貼付でも必ず大きい画素数になるため。バイトサイズでは判定しない＝線画の図面を
  誤除外しないため）。除外したメール画像は `mail-inbox\skipped\` に退避され、後から確認・救済できる。
  寸法が読めない画像だけ `minImageBytes`（既定50KB）未満を除外の代替判定に使う。PDFはこの対象外。
- `weekdayIntervalMinutes` / `nightIntervalMinutes` / `weekendHolidayIntervalMinutes` :
  平日日中30分・平日夜間6時間・土日祝6時間（既定のままでOK）
- `nightStartHour` / `nightEndHour` : 夜間とみなす時間帯（既定 20時〜翌8時）

### 5. Outlookマクロの設定（ユーザー作業・GUI操作が必要）

Outlookの「仕分けルール」単体には添付ファイルをディスクに保存するアクションが無いため、
同等のことを行うVBAマクロ（`outlook-macro.txt`）を使います。新着メールが受信トレイに届くたびに
自動実行され、PDF/PNG/JPEG添付だけを監視フォルダへ保存します。**迷惑メールフォルダは対象外**（受信トレイのみ監視）です。

1. Outlookを開く → 「ファイル」→「オプション」→「リボンのユーザー設定」→ 右側で「開発」にチェックを入れてOK
2. リボンの「開発」タブ →「Visual Basic」をクリック
3. 左のプロジェクトツリーで「Project1 (VbaProject.OTM)」→「Microsoft Outlook オブジェクト」→
   「ThisOutlookSession」をダブルクリック
4. `outlook-macro.txt` の中身をコピーし、開いたコード画面に貼り付ける
5. コード内の `saveFolder = "C:\DrawingWatch\mail-inbox\"` が、手順3で作った実際のフォルダパスと
   一致しているか確認（config.jsonの `mailInboxFolder` と同じにする）
6. マクロを有効化する：「ファイル」→「オプション」→「トラストセンター」→「トラストセンターの設定」→
   「マクロの設定」→ 「すべてのマクロを有効にする」を選択してOK
   （社内・自分専用PCでの利用なので許容範囲ですが、心配な場合はマクロにデジタル署名を付けて
   「デジタル署名されたマクロを有効にする」に変更することも可能です）
7. Outlookを再起動する。起動時にマクロ有効化の確認が出た場合は許可する
8. **注意**: このマクロはOutlookアプリが起動している間だけ動作します。常時受信を反映したい場合は
   監視PCでOutlookを閉じずに起動したままにしてください（すでに「常時接続PC」運用とのことなので問題ないはずです）

### 6. タスクスケジューラへの登録（ユーザー承認後に実行）

PowerShellでこのフォルダに移動し、以下を実行します。

```powershell
cd mail-fax-watcher
.\install-task.ps1
```

タスク名 `DrawingDX-MailFaxWatcher` として、30分おきに起動するタスクが登録されます
（実際の巡回間隔の平日/休日切り替えは index.js が内部で判定します）。
ログは `mail-fax-watcher\run.log` に追記されます。

## 動作確認

1. `config.json` と `serviceAccountKey.json` を設置した状態で、手動で1回実行してみる：
   ```powershell
   cd mail-fax-watcher
   node index.js
   ```
2. コンソールに `✓ 登録完了 id=... ` が出れば、図面DXプラットフォームの「待機」列に該当ファイルが
   表示されることをブラウザで確認してください。
3. FAX共有フォルダにテスト用PDFを1つ置いて再実行し、同様に「待機」に入るか確認してください。

## 既知の制限・注意点

- **PDFのサムネイルは生成しません**（v1では未対応）。一覧では汎用アイコン表示になりますが、詳細画面から
  ダウンロードして中身は確認できます。
- **約950KBを超えるPDFは本文を同期しません**（既存のブラウザ側同期と同じ制限）。この場合、図面レコード自体は
  作成されますが、タグに「サイズ超過:元ファイル要確認」が付きます。メール添付は `mail-inbox\processed\` に
  移動されるので後から見つけられます。FAXは共有フォルダ上の元ファイルはそのまま残ります。
- **ブラウザ側の同期は「ドキュメント全体を上書き」する方式**のため、ウォッチャーが書き込んだ直後にブラウザが
  古い状態で上書きしてしまう理論上の競合があります。ウォッチャーは書き込み後に自動で存在確認・再登録を行う
  自己修復ロジックを持っていますが、万一 `✗ 未確定のため次回再試行` とログに出た場合はそのファイルは
  未処理のまま残り、次回実行時に自動的に再試行されます（データは失われません）。
- 重複登録防止は `state.json`（ファイル名・サイズ・更新日時ベース）で管理しています。このファイルを消すと
  すべてのファイルが未処理扱いに戻り、再登録されてしまうので注意してください。
- **FAX共有フォルダの初回実行時の扱い**: FAX共有には導入以前からの過去ファイルが大量に蓄積されているため、
  初めて実行したタイミングでその時点に存在するFAXファイルは「待機」へ一括登録せず、ベースラインとして
  記録するだけにしています（`state.json` の `faxBaselineSeeded`）。取り込まれるのはベースライン以降に
  新しく届いたFAXのみです。メール添付フォルダ（`mailInboxFolder`）は監視開始後にしか溜まらない前提のため、
  この制限は適用されません。
